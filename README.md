# Openly: email open tracking for Gmail

Openly tells you when the emails you send from Gmail are opened or clicked, **and how sure it is**. Most trackers show a green tick for anything that loads an image, including your own views, scanners and Apple Mail preloads. Openly tells these apart.

## Features

| | Typical trackers | Openly |
|---|---|---|
| Your own views | Often counted | Excluded on your computer automatically. Pause counting from the popup when you check on your phone. "That was me" fixes any single event |
| Scanners and preloads | Counted as reads | Labelled "Possible", never counted. Apple privacy network and Apple Mail preloads are recognised |
| Images blocked | Opens missed | Optional link-click tracking confirms a real person |
| How sure? | Always a green tick | High, medium or low confidence, with the reason |
| Forwarded emails | Invisible | Shows when it sees more than one device |
| Extras | Paid | Follow-up reminders, send-time insights, export and delete all your data |
| Your emails | Footer ad: "Sent with..." | Nothing added that recipients can see |
| Who sees your data | The vendor | Only you. Open source, and you can run your own |

Also included:

- **Web dashboard** at `/app/`, the same dashboard as the extension, works on any browser and phone.
- **Gmail add-on** (Google Apps Script) so you can track emails written in the Gmail phone app.
- **Summary bar in Gmail** above each tracked sent email: opened or not, how many times, when and where.
- **Sign in with a 6-digit emailed code** (hosted mode) or a single secret key (self-hosted mode).
- **Export and delete** all your data from Settings.

## How it works

1. You write an email in Gmail. The extension adds a tiny invisible image that points to your Openly server.
2. When someone opens the email, their mail app loads the image from your server. The server records the time, the type of mail app and a salted fingerprint of the network (never the raw address).
3. The server decides if this looks like a real person, a scanner, a preload or you, and attaches a confidence level.
4. You see the result in the Gmail summary bar, the popup, or the dashboard.

Because the image has to load from the internet, **one server must be online all the time** with a public https address. The extension alone cannot track anything.

## Quick start (try it on your machine)

You only need Node.js 18 or newer and Chrome 113 or newer. No database needed for a first try.

```bash
cd backend
npm install
API_KEY=$(node -e "console.log(require('crypto').randomBytes(32).toString('hex'))") \
AUTH_MODE=apikey DB_DRIVER=memory npm start
```

The server starts on port 8787. Data is kept in memory and is lost when you stop it.

Recipients' mail apps must be able to reach your server, so expose it with a public tunnel:

```bash
npx cloudflared tunnel --url http://localhost:8787
```

Then load the extension:

1. Open `chrome://extensions` and turn on **Developer mode**.
2. Click **Load unpacked** and choose the `extension/` folder.
3. Open the Openly popup, choose **My own server**, and paste the tunnel address and your `API_KEY`.
4. Write an email in Gmail to a second address of yours, send it, and open it there.

## Full setup

There are two ways to run Openly.

| | Hosted (many people sign in) | Self-hosted (just you) |
|---|---|---|
| Sign-in | Email + 6-digit code | One secret API key |
| `AUTH_MODE` | `supabase` | `apikey` |
| Who sets it up | You run one server for everyone | Each person runs their own |

The same code does both. The full guide is in [`docs/DEPLOY.md`](docs/DEPLOY.md). A short version follows.

### 1. Database (Supabase)

1. Create a project at [supabase.com](https://supabase.com).
2. Open the SQL Editor, paste `supabase/schema.sql` and run it.
3. In Project settings > API, copy the **URL**, the **anon key** (public) and the **service_role key** (secret).

### 2. Sign-in by emailed code (hosted mode only)

1. Authentication > Providers > Email: turn it on.
2. Authentication > Email Templates: in both **Magic Link** and **Confirm signup**, add the line `Your Openly code is {{ .Token }}`.
3. Authentication > SMTP Settings: connect a real email sender (Resend, Brevo and Postmark have free tiers). Supabase's built-in sender only allows a few emails an hour.

### 3. Deploy the server

On Vercel:

1. Push the repo to GitHub and import it in Vercel.
2. Set **Root Directory** to `backend`.
3. Add environment variables: `AUTH_MODE`, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` (and `API_KEY` for self-hosting).
4. Deploy, then open `https://your-app.vercel.app/healthz`. It should show `{"ok":true}`.

Other always-on hosts (Railway, Fly.io, your own VPS) also work: run `npm start` inside `backend/`. Avoid hosts that sleep, because the first request after sleeping can take a minute and opens will be missed.

### 4. Point the extension at your server

Edit `extension/config.js`:

```js
globalThis.OpenlyConfig = {
  hostedUrl: 'https://your-app.vercel.app',
  supabaseUrl: 'https://xxxx.supabase.co',
  supabaseAnonKey: '<the anon key>',
};
```

The anon key is meant to be public. **Never** put the `service_role` key in the extension or the add-on.

For self-hosting, leave these empty and choose **My own server** in the popup.

### 5. Keep the web dashboard in sync

The web dashboard is built from the extension's dashboard files. After changing anything in `extension/dashboard/`, `extension/ui/` or `extension/shared.js`, run this from the repo root and redeploy the backend:

```bash
npm run build:web
```

## Configuration reference

Copy `backend/.env.example` to `backend/.env` and fill it in. **Never commit `.env`.**

| Variable | What it does |
|---|---|
| `AUTH_MODE` | `supabase` (many users, email sign-in) or `apikey` (one user, one key) |
| `API_KEY` | Secret key for `apikey` mode |
| `SUPABASE_URL` | Your Supabase project URL |
| `SUPABASE_SERVICE_ROLE_KEY` | Secret server key. Server only |
| `DB_DRIVER` | Leave empty to use Supabase. `memory` for local tries (data lost on restart) |
| `APPLE_RANGES` | `on` downloads Apple's privacy network address list so Apple Mail preloads are labelled correctly. Use on a server that stays on |
| `PORT` | Server port (default `8787`) |
| `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN` | Optional shared Redis cache (Upstash free tier is enough) |
| `SUPABASE_JWT_SECRET` | Only for an older Supabase project that signs tokens with a shared secret |
| `DEFER_WRITES` | `on` (default): the image answers first and the open is saved afterwards. `off` saves before answering. Use `off` if opens go missing |

### Making it fast

- Put the server in the same region as your database. This matters most. For a Mumbai database, pick the Mumbai Vercel region (`bom1`).
- Add Upstash Redis so all server instances share one cache.
- Keep `DEFER_WRITES=on` so a reader's mail app never waits for your database.

## Using Openly

- **Track an email:** write in Gmail as usual. Openly adds the tracking image when you send.
- **Your own views:** excluded on your computer automatically. When you check a sent email on your phone, pause counting first from the popup, or mark the event with **That was me**.
- **Link tracking:** optional and off by default. It confirms a real person when images are blocked. A few spam filters dislike rewritten links.
- **Dashboard:** open it from the extension, or at `https://YOUR-SERVER/app/`. On a phone, use the browser menu > Add to Home screen.
- **Find in Gmail:** every email in the dashboard has a button that searches your Sent mail by recipient, subject and date.
- **Signed in everywhere:** in Settings > Phone and web, use **Open web dashboard** or **Show QR code** and scan it with your phone.
- **Your data:** Settings > Your data lets you export or delete everything.

## Tracking from your phone

The Chrome extension cannot run inside the Gmail phone app, so a small Google Apps Script add-on covers it. Full steps are in [`docs/MOBILE.md`](docs/MOBILE.md). In short:

1. Create a project at [script.google.com](https://script.google.com).
2. Copy `backend/addon/Code.gs` and `backend/addon/appsscript.json` into it.
3. Fill in `BACKEND_URL`, `SUPABASE_URL` and `SUPABASE_ANON_KEY` at the top of `Code.gs`.
4. Run `setupSync` once, then install a test deployment.
5. In the Gmail app, while writing an email, open **Track with Openly** from the compose menu, then send.

The add-on tracks opens only. It cannot rewrite links or tell recipients apart. The subject, recipients and send time are filled in a few minutes after you send.

## API overview

The server exposes a public part (what recipients' mail apps call) and a signed-in part (what the extension and dashboard call).

**Public**

| Route | Purpose |
|---|---|
| `GET /healthz` | Health check |
| `GET /t/:file` | The tracking image |
| `GET /r/:token/:n` | Tracked link redirect |
| `GET /app/` | The web dashboard |

**Signed in (`/api`)**

| Route | Purpose |
|---|---|
| `GET /api/ping` | Check sign-in |
| `POST` / `DELETE /api/pause` | Pause or resume counting your own views |
| `GET` / `POST /api/emails` | List or register tracked emails |
| `GET` / `DELETE /api/emails/:token` | One email's details, or delete it |
| `POST /api/emails/:token/details` | Fill in subject, recipients, send time |
| `POST /api/emails/:token/self-view` | Mark a view as yours |
| `POST /api/events/:id/mine` | "That was me" on one event |
| `GET /api/events/feed` | Recent activity feed |
| `GET /api/insights` | Send-time insights |
| `GET /api/reminders/due` | Follow-up reminders that are due |
| `POST /api/emails/:token/reminded` | Mark a reminder as shown |
| `GET /api/export` | Download all your data |
| `DELETE /api/data` | Delete all your data |
| `POST /api/handoff` | One-time value to sign in on another device |

The database tables (in `supabase/schema.sql`) are `tracked_emails`, `email_events`, `sender_views` and `pause_windows`.

## Contributing

Contributions are welcome: bug fixes, new features, docs, and ideas.

### Report a bug

Open an issue and include:

- What you did, what you expected, and what happened instead
- Chrome version, operating system, and the mail app used to open the email (Gmail, Apple Mail, Outlook...)
- Whether you use the hosted server or your own
- Screenshots or the browser console and server log output, with anything private removed

For a security problem, **do not open a public issue**. Contact the maintainers privately instead.

### Suggest a feature

Open an issue first and describe the problem you want solved, not only the solution. Wait for a quick discussion before building something large, so your work is not wasted.

### Set up for development

1. Fork the repo and clone your fork.
2. Install backend packages: `cd backend && npm install`.
3. Start the server with auto-restart: `npm run dev` (use `AUTH_MODE=apikey DB_DRIVER=memory` and an `API_KEY` for a no-database setup).
4. Load `extension/` unpacked in `chrome://extensions`. After editing extension code, click the reload icon on the extension card, and refresh Gmail.
5. After editing `extension/dashboard/`, `extension/ui/` or `extension/shared.js`, run `npm run build:web` from the repo root so the web dashboard stays in sync.

### Making a change

1. Create a branch from `main`:
   ```bash
   git checkout -b fix/short-description
   ```
   Use `fix/...` for bug fixes, `feat/...` for features, `docs/...` for documentation.
2. Keep the change small and focused. One pull request should do one thing.
3. Add or update tests in `backend/test/` for any backend change.
4. Run `npm test` and make sure it passes.
5. Try the change by hand in Chrome and Gmail if it touches the extension.
6. Commit with a clear message, for example `fix: do not count opens from link scanners`.
7. Push your branch and open a pull request.

### Pull request checklist

- [ ] Tests pass (`npm test`)
- [ ] New behaviour has a test where possible
- [ ] `npm run build:web` was run if dashboard or shared files changed
- [ ] Docs updated (this README or `docs/`) if setup or behaviour changed
- [ ] No secrets, keys or `.env` files in the commit
- [ ] The description explains what changed and why

### Code guidelines

- Plain JavaScript, no build step for the extension. Keep it that way unless there is a strong reason.
- Never put the Supabase `service_role` key in the extension, the add-on or any file that ships to users.
- Do not add anything visible to email recipients (footers, banners, extra images).
- Do not store email bodies. Openly only keeps subject, recipients, tracked links, send time and open events.
- Keep user-facing text short and plain.
- Gmail changes its page now and then. Keep Gmail-specific selectors at the top of `extension/content/gmail.js` so they are easy to fix.

### Good places to start

- Improve scanner and preload detection (`backend/src/lib/ua.js`, `backend/src/lib/sources.js`)
- Fix Gmail selector breakage after a Gmail update
- Add tests for edge cases
- Improve docs and translations
- Send separate tracked copies when one email goes to several people (see Known limits)

## Known limits

- **One email to several people** has one tracking image, so an open cannot be matched to a person. Send separate emails for that.
- **Opening your sent email on your phone** looks like a recipient open. Pause counting first, or use "That was me".
- **Apple Mail Privacy Protection** is recognised when the server can load Apple's address list (`APPLE_RANGES=on`, on a server that stays on) or when Apple Mail loads images right after delivery. It cannot be caught every time.
- **Gmail changes its page** now and then, which can break the in-Gmail parts until the selectors are updated.
- **Link tracking** sends clicks through your server. A few spam filters dislike that, so it is off by default.
- **Phone add-on** tracks opens only and cannot tell recipients apart.
- **Sleeping servers** miss opens. Use a host that stays on.

## Privacy

Openly stores your sign-in email, the subject, recipients and tracked links of emails you track, and the open and click events. It does not read or store email bodies or your inbox. Recipient network addresses are never stored, only a shortened, salted fingerprint. You can export or delete everything at any time. See `docs/PRIVACY.md` for a policy template.

Tracking people's emails is regulated in some places (for example the EU). Be open with your recipients where the law requires it.
